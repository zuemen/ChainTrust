## 1. 一句話商業模式

**驗證即服務（Verification-as-a-Service）**：使用者端永久免費（普惠前提），
機構端按「成功驗證次數」付費；中華電信收基礎設施與資料服務費，平台收驗證與風控加值費。

賣的不是「身分」，而是**省下來的重複 KYC 成本**與**擋下來的詐騙損失**——兩者都是機構
帳上原本就存在、且看得到的支出。

## 2. 價值鏈與收費對象

```
使用者（Holder）           免費 —— 普惠前提，且沒有付費意願的一端不該是收入來源
    │ 出示（最小揭露）
    ▼
驗證方（Verifier）         ★ 主要付費方
  銀行 / 電子支付 / 借貸平台 / 電商             按次計費 + 訂閱
    │ 查信任、查撤銷、要風險分數
    ▼
基礎設施（中華電信）       ★ CHT 收入來源
  PublicCA 信任根 / MID+ 門號驗證 / BaaS / CHT Security 情資
```

| 角色 | 付費項目 | 為什麼願意付 |
| :-- | :-- | :-- |
| 銀行 / 電支（Verifier） | ① 每次成功驗證的 per-verify 費<br>② 反詐風險分數訂閱（含情資）<br>③ 導入與整合一次性費用 | 省下重複 eKYC 的變動成本、降低人頭帳戶損失與裁罰風險、縮短開戶流程降低流失 |
| 發證機構（Issuer，銀行/CHT） | 通常不付費，甚至可分潤 | 發證讓自家 KYC 成為「可被別人採信的資產」，是黏著度而非成本 |
| 中華電信 | — （收費方） | 見 §5 |
| 使用者 | 0 元 | 普惠前提；付費牆會直接殺掉本專案的目標族群 |

**為什麼不向使用者收費**：本專案的目標族群之一就是薄檔（thin-file）族群——學生、
新住民、零工工作者。對他們收費等於讓「普惠金融」這條線自我否定。

## 3. 單位經濟（unit economics）

這是決定商業模式成不成立的核心，因此先把邏輯寫清楚，再填數字。

**買方的替代方案成本**（我們要比它便宜）：
機構自建或外購一次 eKYC 的變動成本 = 證件辨識 + 人臉比對 + 聯徵/戶役政查驗 + 人工覆核。

**我們的成本結構**（每次驗證）：
- 鏈上查詢：`isTrustedIssuer` + `isRevoked` 兩次唯讀呼叫 —— **唯讀不發交易，無 gas 費**，
  只有 RPC 節點成本。（這是 ADR-005 選擇「鏈上明查」而非鏈下快取的附帶好處；
  唯一會發交易、產生 gas 的是撤銷與信任根異動，頻率極低。）
- AI 風險評分：一次 LightGBM 推論，毫秒級 CPU 成本。
- 門號驗證 API（若該次需要）：CHT MID+/Open Gateway 的按次費率——**目前未知，
  是單位經濟裡最大的未知數**，落地談判前無法把毛利算死。

**結論（誠實版）**：邊際成本結構明顯優於「每次都重跑一次完整 eKYC」，因為我們把
「重新驗證一個人」換成「驗證一張已簽章的憑證」——前者是人與資料庫的比對，後者是密碼學運算。
但**確切毛利要等 CHT 的 API 費率**才算得出來，本文不編造一個看起來很漂亮的數字。

> **已查證的更正**：舊版提案書引用的「銀行單次 KYC 審查成本約 US$1,500–3,500」，
> 原始出處是 Fenergo 針對**企業與法人客戶**（corporate / institutional clients）
> 逾 1,000 位 C-level 主管的調查，指的是法人客戶的全流程合規審查成本，
> **不是零售客戶線上開戶的單次 eKYC 成本**，兩者差好幾個數量級。
> 拿它來論證「零售開戶省成本」會被內行評審直接抓到，已從提案書移除。
>
> **台灣的零售 eKYC 單次成本：查無公開數據。** 金管會、銀行局、央行、銀行公會
> 均未公布；LexisNexis 的亞太合規成本研究樣本國家亦不含台灣。因此本專案
> **不以「每戶省下 X 元」作為主論據**，改用下列有一手來源、且對台灣有意義的痛點數字。

### 3.1 可引用的買方痛點數字（皆附出處）

| 數字 | 意義 | 出處 |
| :-- | :-- | :-- |
| **70%** 的金融機構在過去一年因 onboarding 效率不佳而流失客戶（歷來最高） | 慢＝直接掉客戶，這是收入問題不只是成本問題 | Fenergo《2025 Financial Crime Industry Trends Report》(2025-10-08)，樣本新加坡／美國／英國 600 位資深決策者 |

**台中商銀那一案是本專案最有力的市場論據**：問題不在銀行沒有系統，而在
**警示訊號進來了、人卻判斷不出來**（多次警示與跨行通報後仍以「合理交易」結案）。
這正是「可解釋 AI 風險分數 + 跨機構情資」要解的問題——不是取代人，
而是讓人看得到判斷依據。

## 4. 市場規模

採由上而下與由下而上兩路交叉驗證，避免只講一個大到沒有意義的全球數字。

**TAM（台灣，理論上限）**：所有需要確認客戶身分的金融往來次數 —— 開戶、跨行驗證、
高風險交易複核、借貸申請。

**SAM（可服務市場）**：台灣的銀行、電子支付機構、消金/借貸平台中，
願意採信第三方憑證的部分（受 §6 法規條件限制）。

**SOM（三年可取得）**：試點 1 家銀行 → 同集團橫向擴散 → 電支與借貸平台。

### 4.1 台灣在地的分母（皆為官方統計）

| 數字 | 來源 |
| :-- | :-- |
| 本國銀行 **39 家**（含 3 家純網銀）、外銀在台分行 31 家、信合社 23 家 | 中央銀行《金融機構一覽表》(2026-06 底) |
| 專營電子支付機構 **10 家**、兼營 21 家 | 金融聯合徵信中心名單 (2026-08-05) |
| 數位存款帳戶 **2,921.6 萬戶**（2026 Q1），季增 93.4 萬戶；**36 家**本國銀行開辦 | 金管會銀行局 (2026-05-19) |
| 其中純網銀 328.6 萬戶 | 同上 |

**這組數字說明兩件事**：一是數位開戶已是主流通路（近 2,922 萬戶），
身分驗證的量體真實存在；二是**分母不大（39 家銀行 + 10 家專營電支）**，
這是 B2B 生意的典型結構——客戶數少、單客價值高、需要逐家談，
因此試點的參考案例（reference case）比廣告有用得多。

### 4.2 關於市場規模數字的一個誠實警告

外部研究機構的「自主權身分（SSI）市場規模」數字**彼此嚴重矛盾**，不建議單獨引用：
同一家 Grand View Research 就有兩套互斥數字（去中心化身分 2030 年 US$102.0B／CAGR 90.3%
與 2033 年 US$258.18B／CAGR 68.2%）；Precedence Research 預估 SSI 2034 年達 US$1,153B，
比 GVR 的 SSI 2030 年 US$38B 高出約 30 倍。CAGR 66.8%～90.3% 在任何真實產業都不合理。

**本專案的立場**：不以全球 SSI 市場規模作為主論據。對台灣智慧金融組的評審而言，
「台灣有多少警示帳戶、罰了多少錢、多少人在線上開戶」遠比一個誰也驗證不了的
全球市場預測有說服力。

## 5. 中華電信的收入與策略價值（業務連結性）

評分表的「業務連結性」佔初賽 20%。這一節要回答的不是「我們用了 CHT 的產品」，
而是「**這件事讓 CHT 多賺什麼、以及 CHT 為什麼非做不可**」。

### 5.1 四條可計價的收入

| 收入項 | 對應 CHT 既有產品 | 計價方式 |
| :-- | :-- | :-- |
| 門號實名驗證 | MID+（行動身分認證）、GSMA Open Gateway Number Verification / KYC Match | 按次 |
| 信任根與憑證服務 | PublicCA 通用憑證管理中心 | 年費 / 憑證數 |
| 鏈基礎設施 | 區塊鏈即服務平台 BaaS（hicloud，資料主權在台灣） | 節點月費 + 交易數 |
| 反詐情資 | 中華資安國際 CHT Security、GSMA Open Gateway 防詐 API（SIM Swap / Scam Signal） | 訂閱 |

（產品對應的調研來源見 `docs/completeness-roadmap.md` §3.1，含各項「落地仍需確認」的未知數。）

### 5.2 策略價值：從管道商到信任基礎設施

電信業長期的結構困境是被管道化（dumb pipe）。數位身分是少數能讓電信把
「**已經在做的實名制**」變成可計價信任服務的題目——CHT 手上有其他人拿不到的三樣東西：

1. **實名門號**：法定實名登記，是天然的身分錨點。
2. **繳費履歷**：連續數年的按時繳費紀錄，是聯徵之外最接近信用行為的資料。
3. **裝置與網路訊號**：SIM 卡更換、裝置變更、地理跳躍——反詐的高價值訊號，
   而且**只有電信看得到**。

第 3 點正是本專案 AI 反詐引擎吃的訊號，第 2 點正是普惠信譽憑證的來源。

> **誠實邊界**：合成資料上量到的「CHT 訊號使反詐 PR-AUC 提升 +16.45%」
> **不能當作真實效益證據**（那些訊號是以詐欺標籤為條件生成的，是循環論證）。
> 詳見 `docs/model-card.md` §4。對外可宣稱的是「架構上能吃這些訊號、且模型學得到」，
> 不能宣稱「已驗證身分訊號帶來 16.45% 的反詐效益」。錢包 UI 已把這句警語顯示在畫面上。

### 5.3 政策既成事實：電信信任根不是我們的假設，是國家架構的現況

這是本次調研最重要的發現，直接支撐「業務連結性」：

| 事實 | 出處 |
| :-- | :-- |
| 數位發展部「數位憑證皮夾」2025-12-17 試營運，**目前開放一般民眾申請的憑證，只有中華電信、台灣大哥大、遠傳三家電信商的「電信卡」**（另有企業員工卡） | 數位發展部記者會 (2025-12-17)；媒體報導 (2025-12) |
| **數位憑證皮夾主系統建置由中華電信得標** | 數位發展部數位國際司說明，媒體報導 (2025-02-25) |
| 其官方開源專案採 **OID4VCI／OID4VP／SD-JWT／DID／W3C VC** | GitHub `moda-gov-tw/TWDIW-official-app`（讀取於 2026-08-05，MIT License） |
| 跨部會計畫總預算 4.6 億元，推動期程 2024–2027 | 媒體報導引數發部 (2025-02-25) |

**三個推論**：

1. **技術路線已被國家背書**——本專案採用的 W3C VC + SD-JWT + did:key，與政府皮夾同一條路線，
   不是小眾選擇。
2. **電信是國家數位身分的第一批發證者**，而且中華電信同時是系統建置方。
   本專案的「電信信任根」因此不是提案裡的假設，而是**已經發生的事實的延伸**。
3. **政府皮夾定位是「通用身分軌道」，明確聲明「不是支付工具、不是數位身分證」**，
   金融場景的風控與反詐它不做——這正是本專案的位置。

### 5.4 差異化空間：民間對中心化皮夾的信任疑慮

2026-02-09，台灣人權促進會、台灣教授協會、國際特赦組織台灣分會、民間司法改革基金會、
開放文化基金會共五個團體發布聯合聲明，批評數位憑證皮夾「缺乏法律保障基本權，
將淪為下一個台北通」，具體指出：至今無專法規範、**未規劃個資最小化機制**、
無法防止數位足跡被第三方二次利用。

**這對本專案是機會而不是風險**：本專案的核心設計正是這些疑慮的技術解答——
選擇性揭露（驗證方拿不到就無法濫用）、金鑰自持（私鑰在使用者裝置、伺服器不代管）、
以及驗證方無需回問發證者（發證者看不到使用者在哪裡用了憑證，因此無從累積數位足跡）。
在提案中正面引用這份聲明，比迴避它更有說服力。

### 5.5 一個時效性風險（必須主動揭露）

HiPKI / ePKI 根憑證遭 Chrome 撤銷信任一事（見 roadmap §3.1）影響的是**瀏覽器 TLS 信任鏈**，
與本專案用 PublicCA 作「發證者根背書」的用途不同層。但落地簡報若被問到，
必須能分辨這兩件事——被問倒比主動說明糟糕得多。

## 6. 法規前提（決定商業模式能不能成立）

**這一節是商業模式的地基，不是附註。** 詳見 `docs/regulatory-compliance.md`。

最關鍵的一條：**金融監理沙盒不能豁免洗錢防制法**。
《金融科技發展與創新實驗條例》（民國 107 年 1 月 31 日公布，主管機關金管會）第 25 條
明定主管機關得核准實驗期間排除特定法規命令之適用，
**但洗錢防制法、資恐防制法及相關法規命令不得排除**。

推論很直接：「一次 KYC、跨機構重用」**不能靠沙盒繞過 AML 的客戶審查義務**，
必須設計成在 AML 框架內成立——也就是把 ChainTrust 定位為
「**讓既有客戶審查做得更快、更準的工具**」，而不是「**替代客戶審查的捷徑**」。

這反而是好消息：它把產品定位從「幫銀行少做 KYC」（監理上站不住）
校正為「幫銀行更有效率地完成 KYC，並在同一條流程裡加上反詐攔截」（監理上站得住，
而且反詐這一塊正是主管機關現在最在意的）。

## 6.5 普惠金融這條線的證據基礎

**先講誠實的部分**：台灣「無信用紀錄（thin-file）人口數」**查無公開數據**——
聯徵中心 OpenData 專區不含「無法評分人數」，金管會 2025-11-12 向立法院提出的
普惠金融專題報告亦未載明。因此本專案**不宣稱一個台灣 thin-file 人口數字**。

可用的替代母體（皆為官方統計）：大專校院學生 **105.7 萬人**（114 學年度，教育部）、
在台移工 **87 萬人以上**（2026-01，政府資料開放平臺）、新住民約 **60 萬人**（移民署）。
金管會普惠金融衡量指標顯示台灣成年人擁有銀行帳戶比率 93.3%（113 年）——
**有帳戶不等於有信用紀錄**，這正是缺口所在：能存錢，但借不到錢。

**替代資料信用評分的證據**（本專案「電信繳費履歷＝替代信用資料」的學理基礎）：

- **學術**：Björkegren & Grissen《Behavior Revealed in Mobile Phone Usage Predicts
  Credit Repayment》(World Bank Economic Review, 2020) —— 最高風險五分位者違約機率為
  最低五分位者的 2.8 倍；**在 thin-file 樣本上，手機行為模型的表現優於使用徵信中心
  資料的模型**，且對完全無金融紀錄者亦達類似表現。這是本專案最硬的學理支撐。
- **實務**：肯亞 M-Shwari 以電信行為評分放款，累計 2,060 萬筆貸款、
  **54% 的帳戶持有人沒有任何其他銀行帳戶**、90 天以上不良率約 2%。
  （註：此為約 2015 年的 CGAP 數據，屬歷史里程碑案例而非現況。）
- **成熟市場**：Experian Boost 讓使用者自願納入水電與電信繳費紀錄，
  官方揭露平均提升 FICO Score 8 約 14 分。

**與本專案的關係**：上述案例都是「機構去取用電信資料」。本專案的差異在於
**資料以可驗證憑證的形式交到使用者手上，由使用者決定出示給誰、揭露到什麼程度**——
繳費明細留在錢包，對方只看到「信譽等級」。這是同一個普惠邏輯，但把資料主權放對了位置。

## 7. 試點設計（最小可驗證單位）

### 7.1 範圍

| 項目 | 設定 |
| :-- | :-- |
| 參與方 | 1 家銀行（同時是 Issuer 與 Verifier）× 中華電信（信任根 + 門號驗證） |
| 情境 | 線上開戶的**二次驗證**，以及既有客戶的**高風險轉帳複核** |
| 為什麼選這兩個 | 都是銀行既有流程中「已經在做、且做得很痛」的環節，不需要新增使用者行為 |
| 期間 | 3 個月 |
| 使用者規模 | 銀行既有數位客戶中招募自願者 |
| 鏈 | CHT BaaS（合約不變，只換 provider——`ChainGateway` 介面即為此設計） |

### 7.2 成功指標（KPI）

指標要能被銀行的既有報表驗證，否則試點結束後沒有人能證明它有效。

| 面向 | 指標 | 量測方式 |
| :-- | :-- | :-- |
| 效率 | 二次驗證完成時間中位數（對照組 vs 實驗組） | 銀行既有流程埋點 |
| 轉換 | 開戶流程完成率 | 銀行既有漏斗 |
| 防詐 | 高風險交易攔截的 precision / recall；人工複核工時 | 與銀行既有風控結果比對 |
| 隱私 | 每次驗證平均揭露欄位數（目標：1） | 平台側統計 `disclosed` 長度 |
| 普惠 | 薄檔族群的核准率與**分群誤判率** | 見下方警告 |

> **必須做的公平性檢查**：`docs/model-card.md` §6 已承認一個結構性張力——
> 反詐模型的高權重特徵（`account_age_days` 重要度第 2、`vc_age_days` 第 3、
> 規則層的 `NEW_ACCOUNT`／`NO_REALNAME`）**正是薄檔族群天生會踩到的訊號**。
> 一個剛申辦門號、剛開戶的新住民，即使完全合法，也會因為「新」而被加分。
> 試點**必須**做分群誤判率量測；若確認不成比例，設計上的解法是讓
> `FinancialReputationCredential` 反向抵銷這類風險分數——用「薄檔但有信譽」
> 取代「薄檔即風險」。**這件事不做，普惠金融那條線在道德上是空的。**

### 7.3 試點前必須完成的技術前置

| 前置 | 現況 |
| :-- | :-- |
| 合約部署上真鏈 | ❌ 尚未部署（唯一未完成的 P0，見 `docs/amoy-deploy-checklist.md`） |
| 第三方安全稽核 | ❌ 目前只有自我稽核（`docs/security-audit-2026-08.md`，4 Critical + 17 High 已修） |
| 金鑰復原機制 | ❌ 目前只有密語加密備份匯出；**丟手機 = 憑證全失**。落地必須有電信端復原管道（門號 + SIM 綁定），這也是 CHT 的差異化機會 |
| 人工複核佇列 | ❌ `review` 決策目前沒有對應的人工作業流（model card §8 已記載） |
| 模型重訓與漂移監控 | ❌ 目前是一次性手動訓練，無排程、無 PSI 監控 |
| OID4VCI / OID4VP 對齊 | ❌ 目前是自定 API；標準已定案（見 `regulatory-compliance.md`），跨錢包互通性需要它 |

**這張表不該被藏起來。** 評審與合作方問「還缺什麼」時，能精確回答缺什麼、
以及為什麼現在還沒做，比宣稱「都做完了」可信得多。

## 8. 三年路線

| 階段 | 目標 | 關鍵動作 |
| :-- | :-- | :-- |
| Y1 上半 | 試點成立 | 上真鏈、第三方稽核、1 家銀行試點、法規諮詢確認 AML 定位 |
| Y1 下半 | 可複製 | OID4VCI/VP 對齊、金鑰復原、人工複核流程、模型治理上線 |
| Y2 | 橫向擴散 | 同集團其他機構、電支業者；反詐情資形成跨機構效益 |
| Y3 | 生態 | 對接數位發展部數位憑證皮夾，從「自建錢包」變成「數位皮夾生態的金融應用層」 |

**護城河的誠實評估**：技術本身（DID/VC/SD-JWT）是公開標準，不構成護城河。
真正難複製的是「**電信級信任根 + 只有電信看得到的反詐訊號 + 跨機構情資網路效應**」——
前兩者是 CHT 的資產，第三者需要時間累積。這也是為什麼本專案的定位是
**與電信深度綁定**，而不是做一個誰都能做的通用錢包。
